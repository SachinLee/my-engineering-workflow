# Spec Delta

## Purpose

提供一个小而可执行的方案简化准则及可选评估方法，使规划提示能减少无依据的防御性机制，同时持续满足用户验收条件和必要正确性不变量。

## ADDED Requirements

### Requirement: 防御性机制必须有可追溯依据

正式方案中的非平凡 fallback、retry、compensation、recovery、兼容分支、配置开关或扩展点 SHALL 对应明确的 AC 或必要不变量、一个具体可达的失败场景、现有处理不足之处及省略后果。缺少这些依据时，方案 SHALL NOT 将该机制列为实现功能；尚未核实的担忧可以作为风险记录。

#### Scenario: 提案包含无证据的重试分支

- **WHEN** 设计者无法指出触发重试的可达失败、现有错误传播为何不足或省略后的契约影响
- **THEN** 该重试分支不进入 design 或 tasks
- **AND** 不得为普通错误处理逐行增加额外论证清单

#### Scenario: 删除机制会破坏必要不变量

- **WHEN** 删除候选机制会在明确场景违反 AC、安全或数据完整性不变量
- **THEN** 设计者保留该机制或提出能保持同一不变量的更简单方案

### Requirement: 规划提示改动可用配对消融评估

当变更明确声称可减少规划过度设计时，工作流 SHALL 提供可选的配对提示消融流程：同一批案例分别使用当前提示和候选提示，在匹配的模型、输入、上下文和工具条件下生成独立方案，并按盲评 rubric 比较。普通单个任务不要求执行此实验。

#### Scenario: 评估用于简化规划的新提示规则

- **WHEN** 团队评估一项旨在减少无依据防御机制的新规划提示
- **THEN** 评估使用独立会话分别运行 A/B 提示并隐藏条件后评分
- **AND** rubric 至少记录无依据机制、AC/必要不变量覆盖、可验证性和实现工作量

#### Scenario: 试点没有减少无依据机制或损害必要覆盖

- **WHEN** 试点案例中无依据机制没有在多数案例减少，或任一必要 AC/不变量出现回退
- **THEN** 结果不作为采纳新提示规则的正向证据，并记录为未通过或需复测
- **AND** 单纯的方案篇幅或 token 减少不得计作成功

### Requirement: 消融评估不得移除生产保护

规划简化 SHALL NOT 通过在生产系统移除必要安全、授权、数据完整性、并发正确性或资源清理保护来验证方案。高风险机制只可通过方案反事实、隔离测试或不影响生产数据与授权的验证方式评估；小样本试点 SHALL 标记为方向性证据而非统计显著结论。

#### Scenario: 评估涉及授权或持久数据保护

- **WHEN** 候选机制保护授权边界或持久数据不变量
- **THEN** 消融仅在推演或隔离环境中进行，不改变生产保护
- **AND** 报告说明验证方式及其限制
