# 提案：用证据约束方案中的防御性设计

## Why

当前 `Evidence-Based Planning` 已要求防御机制对应具体失败路径并说明现有保护不足，但尚无行为评估证明规划提示能否让 GPT 遵守这一规则。需要为“减少过度设计”的方案指导提供轻量、可复现的对照方法，同时明确不得为了简化而删除必要的安全、数据完整性或其他正确性保护。

## What Changes

- 在现有方案指导中加入最小方案反事实：删除某个非平凡防御机制后，只有在可达场景会违反明确 AC 或必要不变量时才保留。
- 提供可选、按需的规划提示 A/B 消融协议和盲评 rubric，用于评估有意降低过度设计的提示或规则调整。
- 仅在提示策略本身发生变化时运行一次小型配对试点；不要求普通任务逐项消融，不增加常驻 agent、自动 gate 或 LLM 评测基础设施。
- 保护性机制仅在隔离测试或方案反事实中评估；不得在生产环境中移除必要保护。

## 范围与约束

- 只调整本仓库 canonical 规划指导和配套评估材料，不改用户的 GPT/模型供应商配置。
- 试点建议使用 10–12 个脱敏、覆盖简单/普通/高风险任务的案例；固定模型、上下文和工具，使用独立会话生成 A/B 方案，并在不知道条件的情况下按 rubric 评审。试点用于发现方向，不宣称统计显著。
- 在实际运行评估前，不声称新规则已改善方案质量；案例、评分结果及未运行项需可追溯。

## 验收标准

- [ ] AC-001：canonical planning guidance 要求非平凡防御机制关联到明确 AC/不变量、可达失败场景、现有保护不足和省略后果；无具体证据时不把猜测写成方案功能。
- [ ] AC-002：指导明确要求保留必要安全、数据完整性、并发正确性和资源清理保障，且不要求为普通错误处理新增逐项清单。
- [ ] AC-003：提供可选配对消融流程与盲评 rubric，评估无依据机制数量、AC/必要不变量覆盖、可验证性和实现工作量；只有无依据机制在多数案例减少且必要 AC/不变量零回退，才记为有积极信号，篇幅或 token 减少不能单独判成功。
- [ ] AC-004：试点流程固定同一模型与输入条件、隔离 A/B 会话并隐藏条件；高风险保护只做反事实/隔离验证，不在生产中移除。
- [ ] AC-005：规则与评估材料有测试或可执行核对；未实际运行的模型试点评价为 `NOT RUN`，不推断实验结论。

## Capabilities

### New Capabilities
- `planning-simplicity-evaluation`：证据约束下的方案简化准则及按需的规划提示消融评估。

### Modified Capabilities
- 无。仓库尚无已归档的主规格，本 change 新增独立 capability。

## Impact

`skills/run-engineering-workflow/references/workflow-governance.md`、`skills/plan-solution/SKILL.md`、`evals/`、相关合同测试及本 change 的 capability spec。不得同步改写旧项目级 skill 副本；由标准安装流程发布 canonical 版本。
