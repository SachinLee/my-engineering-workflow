# 限制交付审核轮数

## 目标
把每次交付的默认审核收敛为一次完整独立审核，存在阻断 findings 时最多一次定向复核。收尾仅复用和记录证据，默认只使用 `workflow-reviewer`，不叠加 `code-reviewer`。

## 现状与问题
现有单 reviewer 合同限制了每轮代理数量，但各入口仍要求材料变更后完整重审；`finish-with-evidence` 又要求运行仓库验证。修复、收尾和跨会话续接容易重启审核循环。现有 OMP gate 只识别 `Active task:`，不保障新 `Active change:` 合同。

## 范围内
- 在 `quality-profiles.md` 集中交付级轮数、阻断判据、定向复核、预算用尽及重新完整审核的授权规则。
- 更新主路由、命令、review/finish 技能、治理引用、Root/OMP/Pi reviewer 源定义和活跃说明。
- 先改合同测试和场景，再修改规则；通过现有安装器验证四种 harness 产物并同步本项目受管副本。

## 范围外
- 不修改外部 `omp-extensions`、宿主全局配置或第三方 `code-reviewer` 定义；不声称运行时去重已经修好。
- 不增加审核调度器、自动 injector、配置系统或第二套状态存储。
- 不改变用户验收、归档权限，也不修改其他 change 或 legacy 记录。

## 假设与约束
- 用户要求执行此前优化方案，已确认新建本 change；新增关于 `code-reviewer` 重复的要求一并纳入。
- `standard`：这是会改变代理执行行为的规则改动，不能按纯文档 `lightweight` 跳过独立审核。
- 以公开技能/代理/命令文本和安装产物为测试接缝，沿用 `tests/contracts.test.js`，不新增模拟调度引擎。
- 本工作区已有多项未提交改动，`artifacts/baseline.json` 保留本次选定文件的实施前内容；仅对比并修改本 change 增量。

## 验收标准
- [ ] AC-001: 交付级预算与单审核代理
  - 场景：Standard / Critical 交付完成，或完成一个实现切片。
  - 动作：主路由选择审核阶段。
  - 期望：交付范围完成并通过相关检查后恰好一次完整 `workflow-reviewer` 审核；切片仅做相关检查。默认不追加 `code-reviewer` 或 Matt 原生审核，风险只增加相关验证深度。
  - 验证方法：预算、入口、代理合同断言与场景覆盖。
- [ ] AC-002: 阻断项修复最多一次定向复核
  - 场景：完整审核发现违反 AC/规则/正确性、安全或数据不变量的具体缺陷。
  - 动作：主会话集中修复并运行受影响检查。
  - 期望：最多一次定向复核，仅核对原 findings、修复 diff 和直接受影响路径；预算用尽或出现未解决/新阻断问题时报告 `blocked`，不循环也不假称 `CLEAN`。
  - 验证方法：定向模式、阻断判据、停止条件的正反合同断言。
- [ ] AC-003: 建议不阻断，预算跨会话保留
  - 场景：仅有可选简化/风格建议，或会话恢复、修复产生新快照。
  - 动作：选择下一步。
  - 期望：非阻断建议记录即可；预算记录在现有 change artifacts，续接或快照变更不自动重置。`INVALID` 仅允许一次未形成有效报告的受控替换，不绕过有效轮数预算。
  - 验证方法：合同断言、续接与 INVALID 场景。
- [ ] AC-004: 收尾只消费证据
  - 场景：有效同 change 同材料的验证和审核证据已经存在，或发现证据缺口。
  - 动作：调用 `finish-with-evidence`。
  - 期望：仅核对范围与证据关联、记录结果并交接；不派审核代理、不直接重新运行验证。缺失/过期证据返回主路由补相关检查，不降低通过标准；追加报告/交付记录不自失效。
  - 验证方法：finish 合同正反断言。
- [ ] AC-005: 重新完整审核必须经用户决定
  - 场景：验收标准、接口、安全边界或实现方案大幅变化，原审核覆盖失效。
  - 动作：主路由报告失效范围。
  - 期望：停止自动重审，请用户决定重新完整审核或拆分交付；记录授权和新边界，不能凭 snapshot 变化自行重置预算。
  - 验证方法：扩大范围及重新授权场景断言。
- [ ] AC-006: 安装一致与验证如实记录
  - 场景：安装到隔离项目及同步当前项目受管技能。
  - 动作：使用 `scripts/install.ps1` 和现有测试。
  - 期望：四种 harness 的预算和技能一致，Root/OMP/Pi 模型与工具限制保持；安装到 Pi 项目使用 `.agents/skills`，不手改旧 `.pi/skills` 镜像。记录 RED/GREEN、独立审核和 NOT RUN，不归档。
  - 验证方法：全套 Node/Python 测试、隔离 All 安装内容比对与项目安装。

## 未决与阻塞决策
无产品阻塞决策。真实宿主自动派发遵循度和外部 OMP gate 修复不在本次实现范围，验收时明确区分合同测试与运行时行为。
