# 审核预算优化方案

## 方案与改动边界
以 `skills/run-engineering-workflow/references/quality-profiles.md` 为唯一审核预算源，增加交付级完整/定向模式和停止条件。其余技能与代理引用该合同，不各自增加审核调度。

## 组件与职责
- 主路由唯一调度：切片检查 → 交付验证 → 完整审核 → 可选集中修复与定向复核 → 收尾。
- reviewer 只返回发现和覆盖，完整模式覆盖所有相关材料；定向模式覆盖原阻断 findings 与修复影响，不新建综合审查阶段。
- finish 核对范围和证据关联并记录交接；缺口返回主路由，不自行补一套检查。
- 现有 `artifacts/review.md` 或 `artifacts/verification.md` 保存范围/轮数/报告，不创建新状态系统。

## 不变量与失败模式
对应 AC-001～AC-005：独立性、完整工作区覆盖、相关仓库验证、用户验收及归档边界不变。预算限制的是自动次数，不降低通过标准；未解决阻断或材料扩大时停止并请求用户决定。
`Review mode: full | focused` 表达明确模式。`Review retry: invalid` 保留一次仅对无有效结果派发的替换；不能替换真实 FINDINGS。预算跨会话、修复快照和单独调用 finish 保留。用户重新授权时明确新的审核边界并保留旧证据。

## 测试与实施
测试接缝为用户/代理实际消费的技能、命令、代理定义和安装产物。沿用现有 Node 静态合同测试与 eval 场景，不用一个新模拟调度器测试自己。
切片 1 落实预算、路由和单审核身份；切片 2 落实完整/定向执行与证据型收尾；每片先 RED 再 GREEN。最后全套测试与隔离 All 安装内容比对，当前项目通过安装器同步受管副本。

## 备选方案与否决理由
- 删除所有独立审核：降低必要正确性保障，否决。
- 无论修复大小都完整重审：继续造成重复，否决。
- 先做新运行时调度系统：本仓库是薄编排层且 OMP gate 外部维护，扩大目标，否决。

## 兼容性、发布与回滚
保持模型/工具限制、`Both`/`All`、无自动 injector 及 legacy 只读不变。使用 `scripts/install.ps1` 发布受管文件，不改宿主全局设置；旧 `.pi/skills` 非当前安装目标。
本工作区原有修改从 `artifacts/baseline.json` 区分；回滚只撤销本次相对 baseline 的 patch 并重新安装，不恢复到 HEAD 覆盖用户既有修改。

## 验证边界
静态合同和场景一致性能够证明交付文本与安装产物包含明确规则，不能证明所有模型必然服从。外部 OMP gate 与真实各宿主自动派发运行本次均不执行，不宣传已具备运行时强制预算。
