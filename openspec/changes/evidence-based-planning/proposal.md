# 基于证据的最小方案规划

## 目标与现状

规划应先判断行为是否需要存在，再选择最小实现。当前 `plan-solution` 从复用开始，Ponytail 只作为末尾提醒，没有要求新增兜底、降级、恢复等机制说明依据。用户已确认创建 `evidence-based-planning` 并按此前分析优化工作流。

## 范围内

- 共享治理定义额外复杂度的举证责任，澄清和规划显式读取该规则。
- 澄清项目阶段、适用契约、真实兼容和恢复需求；不增加固定提问仪式。
- 规划先判断必要性；无依据机制不得进入方案或执行任务，不确定性保留为风险。
- 保留安全、数据完整性、并发一致性及其他必要正确性保障。
- 更新行为场景契约，运行修改前后模型规划演练，并独立复核；通过安装器同步项目内副本。

## 范围外

安装 Ponytail 或其他上游插件、修改上游 skill、引入分类器/阈值/运行时校验器、改变质量档位与用户验收/归档流程、替业务项目设计恢复系统。

## 假设与约束

- 档位：`standard`；主会话实施，独立 reviewer 复核。
- 项目阶段从用户与仓库事实判断，未知时不默认生产场景；只有影响行为/风险的缺口才提问。
- 新规则集中于现有共享治理，不复制上游 skill，不添加依赖或配置。
- 模型演练是抽样行为证据，不保证所有未来模型与会话必然遵守。

## 验收标准

- [ ] AC-001: 开发阶段不扩展恢复需求
  - 场景：节点日志功能，开发阶段无历史数据；要求唯一记录、正常/异常结束可保存和查询。
  - 动作：按工作流规划。
  - 可观测结果：覆盖主路径与必要唯一性/线程安全；不自行建设历史恢复、所有权状态机、提交不明确查证、降级链路。
  - 验证方法：修改前后模型演练 `planning-development-logs`。
- [ ] AC-002: 必要保障不因简单而删除
  - 场景：明确安全、数据完整性/并发要求，现有事务/约束足以承担保障。
  - 动作：面对要求删掉保障的简单化建议进行规划。
  - 可观测结果：保留必要约束与正常/异常路径，说明依据并复用现有机制；拒绝推测性分布式恢复。
  - 验证方法：模型演练 `planning-required-safeguards`。
- [ ] AC-003: 未知事实不变成需求
  - 场景：项目阶段或兼容范围未知，或模板含发布/回滚等章节。
  - 动作：澄清并规划。
  - 可观测结果：只追问实质改变行为的缺口，不假定线上存量，不为模板填满而建设双写、灰度或恢复；仅明确适用的段落。
  - 验证方法：模型演练 `planning-unknown-stage`、`planning-template-pressure`。
- [ ] AC-004: 失败处理与假成功区分
  - 场景：已有标准错误契约，无降级可用性需求；调用失败时有人建议缓存旧结果或返回空值。
  - 动作：规划失败路径。
  - 可观测结果：维持明确错误传播与一致性；无依据 fallback 不进入任务；不报告伪成功。
  - 验证方法：模型演练 `planning-error-contract`，Node 契约检查、安装诊断和 OpenSpec 校验。

## 能力与影响

新增规范能力 `evidence-based-planning`。影响共享治理、需求澄清、方案规划和路由读取约定；其余 agent/质量档位/安装逻辑保持不变。交付状态止于 `awaiting-acceptance`。
