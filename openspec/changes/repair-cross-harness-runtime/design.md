# 设计

## 安装与启动

安装器保留现有共享技能和角色同步，移除外部 gate 源路径、前置检查和复制动作。用户原有扩展由原安装方管理。同步项目受跟踪的 overlay 与 canonical 配置。`ompw` 保持现有 overlay 选择顺序，README 将普通 `omp` 设为默认入口。

## 诊断

doctor 检查随工作流提供的共享技能和角色，并检查存在且适用的用户与项目技能白名单。兼容入口及旧扩展缺失不阻断结果。实际派发需要运行证据，静态诊断报告 `UNVERIFIED`。

## 角色路由

原生 `scout` 承担只读探查，`workflow-planner` 服务专项规划，`workflow-reviewer` 保留正式 OpenSpec 审查协议。主会话根据 change 和审查证据控制轮次。原生 `task` 通过隔离探针验证写入边界、测试证据、模型与 prewalk 后可成为实现默认角色。探针受阻时继续使用 `workflow-implementer`。

## 验证与回滚

先提交到工作区的契约测试应覆盖安装成功、预演副作用、升级保留扩展及 doctor 输出，再改对应行为。真实运行探针与静态结果分别记录。回滚可通过恢复本次安装、诊断、配置和路由改动完成。
