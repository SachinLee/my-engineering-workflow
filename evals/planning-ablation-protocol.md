# 规划提示消融 A/B 盲评协议（可选、一次性）

## 目的与适用范围

本协议评估"防御机制必须有可追溯依据 + 反事实删除判据"的规划提示变化是否能减少无依据防御机制，同时不损害必要保护。协议仅供提示策略本身变化时按需执行一次；普通任务不要求逐项消融。不引入常驻 runner、agent、MCP 或 LLM 评测基础设施。

## 准备（冻结输入）

- 使用 `evals/planning-ablation-cases.json` 中 10 个脱敏合成案例（`source: synthetic`），覆盖简单/普通/高风险任务。
- 固定同一模型与实际上下文注入方式；记录可确认的模型版本、推理/采样设置、工具集与会话配置，无法控制的设置写明限制。
- 先冻结本次变更前的完整提示为 A；B 复用相同提示，仅加入本次反事实条款及 `plan-solution` 对它的引用。保存两臂完整提示与差异；核对实际加载的 skill 与指令，确保 A 不会从其他入口读到候选条款。
- 生成器只接收案例的 `prompt` 和相同的冻结上下文；`temptations` 与 `necessary_safeguards` 留给盲评，不作为方案生成提示。
- 各臂使用独立会话生成方案，禁止共享对话历史或中间产物。

## 执行

1. 每个案例在 A 与 B 会话分别生成方案；输出按案例保存为匿名文件。
2. 评分前去掉会话标识与臂标识，随机打乱顺序。
3. 由不了解臂归属的评审按下方 rubric 逐案例评分，保留匿名输出供复核。

## 盲评 rubric

| 维度 | 说明 |
| --- | --- |
| 无依据机制数 | 缺少明确 AC/不变量、可达失败、现有保护不足与省略后果的非平凡 fallback/retry/compensation/recovery/兼容分支/配置开关/扩展点数量 |
| AC/必要不变量覆盖 | 安全、数据完整性、并发一致性、资源清理等必要保障是否保留；评审记录是否有任一必要覆盖回退 |
| 可验证性 | 方案是否给出可运行验证命令与可观察结果，而非空泛断言 |
| 实现工作量 | 相对最小完整解的实现与维护成本；篇幅或 token 减少不单独计作成功 |

按独立机制计数，同一机制的重复表述只计一次；逐例记录 B 数量减 A 数量，负数为减少。必要覆盖逐项核对案例的要求与 `necessary_safeguards`，缺失或无法确认均不能记为零回退；可验证性与工作量分别给出理由，不合成为加权总分。

## 判定

- 正向信号：多数案例（>5/10）无依据机制减少，且全部案例必要 AC/不变量覆盖零回退。
- 不通过/需复测：未满足上述任一条件，或任一必要机制被删除。
- 纯篇幅/token 下降不构成成功证据。

## 约束

- 高风险保护（授权、事务一致性、持久数据、资源清理）只做方案反事实或隔离验证，绝不在生产移除或验证。
- 小样本结果仅作方向性证据，不宣称统计显著。
- 无法确认同一有效模型、独立会话或盲评条件时，结果如实记录为 `NOT RUN` 并逐案例说明原因，不从规则文本或合同测试推断模型行为已改善。

## 输出

- 每案例记录：A/B 生成状态、评分、无依据机制变化、必要覆盖、可验证性、工作量。
- 结果写入本 change 的 `artifacts/verification.md`；未运行案例分析标 `NOT RUN`。
